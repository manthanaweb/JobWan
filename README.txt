JOBWAN 4.2 — Individual vs Organization, made concrete with a simulated HR view
=================================================================================

วิธีใช้
1. แตกไฟล์ ZIP
2. เปิด index.html ด้วย Chrome / Edge / Safari
3. ข้อมูลถูกเก็บใน localStorage ของเบราว์เซอร์นี้เท่านั้น
4. ไปหน้า "ตั้งค่า" > กรอกรหัสองค์กรอะไรก็ได้ (โหมดสาธิต) > กดปุ่ม "ดูตัวอย่างแดชบอร์ด HR"

สิ่งที่เพิ่มในรอบนี้: ทำให้ 4 ข้อแยกรายบุคคล/องค์กรจับต้องได้จริงในแอป ไม่ใช่แค่คำอธิบาย

1) เนื้อหา vs ตัวเลขสรุป — หน้าตั้งค่าโชว์ "ตัวอย่างสิ่งที่องค์กรจะเห็นจากคุณ" คำนวณจากไดอารี่จริงของคุณ
   (เช็กใจกี่วัน/แนวโน้มอารมณ์) ให้เห็นชัดว่ามีแค่ตัวเลขสองค่านี้เท่านั้นที่ข้ามไป ไม่ใช่ข้อความที่เขียน

2) k-anonymity — แดชบอร์ด HR (จำลอง) มีปุ่มปรับขนาดทีม (2/3/5/8/12 คน) ให้เห็นด้วยตาตัวเองว่าทีม
   ต่ำกว่า 5 คนจะถูกล็อกไม่ให้แสดงผลรวม (ไอคอนล็อก + คำอธิบาย) พอถึง 5 คนขึ้นไปถึงจะปลดล็อกเห็นค่าเฉลี่ย
   ทีมกับสัญญาณเตือน (ข้อมูลสมาชิกอื่นเป็นข้อมูลจำลองแบบสุ่ม มีป้ายกำกับชัดเจนว่าไม่ใช่ข้อมูลจริง)

3) สมัครใจ ไม่บังคับ — ฟอร์มเข้าร่วม/ออกจากองค์กรเหมือนเดิม เน้นย้ำข้อความว่าไดอารี่ส่วนตัวไม่กระทบ

4) โมเดลธุรกิจแยกชัด — แดชบอร์ด HR มีส่วน "แผนและการใช้งาน" โชว์ "แผนองค์กร: Business" และ
   "ที่นั่งที่ใช้ไป" แบบตัวอย่าง เทียบกับย่อหน้าใหม่ในฝั่งพนักงานที่บอกตรง ๆ ว่า "รายบุคคลใช้งานฟรีเสมอ
   ไม่ต้องสมัครสมาชิก" — แยกคนละโมเดลธุรกิจให้เห็นในหน้าจอเดียวกัน

ฟีเจอร์ต่อเนื่องที่เพิ่ม: HR ตั้งค่าลิงก์ EAP จากแดชบอร์ด แล้วลิงก์นั้นจะไปโผล่จริงในหน้า "ค้นหาความช่วยเหลือ"
ของฝั่งพนักงานทันที (เก็บในเครื่องเดียวกัน เพื่อสาธิตว่า HR ควบคุมอะไรได้บ้างในระบบจริง)

หมายเหตุสำคัญ
- แดชบอร์ด HR (จำลอง) เข้าถึงได้จากปุ่มในหน้าตั้งค่าเท่านั้น ไม่อยู่ในเมนูหลัก เพราะเป็นมุมมอง
  ของคนละบทบาท (HR ไม่ใช่พนักงาน) ในระบบจริงต้องมีการยืนยันตัวตนแยกต่างหากสำหรับ HR
- ข้อมูลสมาชิกทีมอื่น ๆ ในแดชบอร์ดเป็นข้อมูลสุ่มเพื่อสาธิตเท่านั้น ของจริงต้องมี backend รวมข้อมูล
  จากพนักงานที่เชื่อมบัญชีจริงทั้งหมด
- Prototype นี้ยังไม่มีระบบสมาชิกหรือ cloud database ข้อมูลทั้งหมดอยู่ใน localStorage ของเบราว์เซอร์เครื่องนี้เท่านั้น
- Mind Check Point และ Mind Report เป็น wellness signal จากข้อมูลที่ผู้ใช้บันทึกเอง ไม่ใช่การวินิจฉัยโรค
- ก่อนเปิดใช้จริงควรเพิ่ม Privacy Policy, Consent, ระบบรักษาความปลอดภัย และช่องทางช่วยเหลือสุขภาพจิตที่เป็นทางการ
